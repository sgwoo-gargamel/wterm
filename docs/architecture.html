1. 요구사항 정리

기능상세
시리얼 접속포트 선택(자동 목록), baud rate 설정 (data bits / parity / stop bits는 기본값 8-N-1, 추후 확장)
SSH 접속IP(호스트), 포트(기본 22), 사용자 ID. 인증: 비밀번호 (추후 키 파일 확장)
Telnet 접속IP(호스트), 포트(기본 23), 사용자 ID (로그인 프롬프트 자동/수동 입력)
화면 분할타일(tile) 방식 — 가로/세로 분할을 반복해 임의의 레이아웃 구성, 각 타일에 독립 세션
이력 저장연결 설정(프로파일) 목록을 로컬에 저장, 재접속 시 선택만으로 연결

2. 기술 스택 개요

프로젝트는 이미 Tauri 2 + SvelteKit(Svelte 5, static adapter) + Vite 6 + TypeScript로 스캐폴딩되어 있으며, 이 구성을 그대로 사용한다.

레이어기술역할
셸 / 백엔드Tauri 2 (Rust)시리얼/SSH/Telnet I/O, 세션 관리, 네이티브 API
프론트엔드SvelteKit + Svelte 5 (runes)UI, 타일 레이아웃, 터미널 렌더링
비동기 런타임tokio세션별 read/write 태스크 (Tauri 2 내장 런타임)
핵심 원칙: 모든 네트워크/시리얼 I/O는 Rust 측에서 수행하고, 프론트엔드는 바이트 스트림을 렌더링하는 뷰 역할만 한다. WebView에서는 raw TCP/serial 접근이 불가능하므로 이 분리는 필수이며, 보안·성능 면에서도 유리하다.

3. 라이브러리 선정

3.1 Rust (백엔드) 크레이트

용도선정채택대안선정 이유
시리얼 통신 serialport tokio-serial 사실상 표준 크레이트. 포트 열거(available_ports()) 지원, Windows/macOS/Linux 모두 동작. 블로킹 API지만 세션당 전용 read 스레드로 감싸면 충분하며, async 래퍼(tokio-serial)보다 의존성이 단순함.
SSH 클라이언트 russh ssh2 (libssh2 바인딩) 순수 Rust + tokio 네이티브 async. C 라이브러리 빌드 의존성이 없어 Windows 크로스 빌드가 깔끔함. PTY 요청, 창 크기 변경(window-change), 비밀번호/공개키 인증 모두 지원.
Telnet tokio TcpStream + 자체 IAC 처리 libtelnet-rs Telnet은 TCP 위에 IAC(0xFF) 옵션 협상만 얹은 프로토콜. 필요한 협상(ECHO, SGA, NAWS, TERMINAL-TYPE)만 200줄 내외로 직접 구현하는 편이 외부 크레이트 유지보수 리스크보다 낫다.
이력/설정 저장 tauri-plugin-store rusqlite 공식 플러그인, JSON 파일 기반 key-value. 프로파일 수십~수백 개 수준에는 DB가 과함. 프론트/백엔드 양쪽에서 접근 가능.
직렬화 serde / serde_json — 이미 포함됨. IPC 페이로드와 프로파일 직렬화에 사용.
에러 처리 thiserror anyhow 커맨드별 에러 타입을 프론트에 구조화된 형태로 전달하기 위해 라이브러리 스타일인 thiserror 채택.

4. 전체 아키텍처

┌────────────────────────── WebView (SvelteKit) ──────────────────────────┐
│                                                                         │
│  TileLayout (이진 트리)                                                  │
│  ├─ Pane #1 ─ TerminalView(xterm) ─┐                                    │
│  ├─ Pane #2 ─ TerminalView(xterm) ─┼─ sessionStore (Svelte 5 runes)     │
│  └─ Pane #3 ─ ConnectDialog        │   · 세션 상태 / 활성 타일           │
│                                    │                                    │
│  ProfileList (연결 이력)            │                                    │
└────────────┬───────────────────────┴────────────▲───────────────────────┘
             │ invoke(command)                    │ Channel<Vec<u8>> (출력 스트림)
             │ session_write / resize / close     │ + 상태 이벤트 (connected/closed/error)
┌────────────▼─────────────────── Tauri (Rust) ───┴───────────────────────┐
│                                                                         │
│  SessionManager  ─ HashMap<SessionId, SessionHandle>                    │
│       │                                                                 │
│       ├─ Session (trait: write / resize / close)                        │
│       │    ├─ SerialSession  ── serialport (전용 read 스레드)            │
│       │    ├─ SshSession     ── russh (tokio 태스크, PTY channel)        │
│       │    └─ TelnetSession  ── TcpStream + IAC 협상 (tokio 태스크)      │
│       │                                                                 │
│       └─ 각 세션의 read 루프 → Channel로 바이트 push → xterm.write()      │
│                                                                         │
│  ProfileStore ── tauri-plugin-store (profiles.json)                     │
└─────────────────────────────────────────────────────────────────────────┘

데이터 흐름

  1. 연결: 사용자가 다이얼로그에서 설정 입력 → session_open(profile, channel) invoke → Rust가 transport 연결 후 SessionId 반환, 프로파일을 이력에 저장.
  2. 출력 (device → 화면): 세션 read 루프가 받은 바이트를 Tauri 2 Channel<Vec<u8>>로 push → 프론트에서 term.write(bytes). 이벤트 시스템보다 Channel이 스트리밍에 적합(순서 보장, 브로드캐스트 오버헤드 없음).
  3. 입력 (키보드 → device): xterm onData → session_write(id, data) invoke → transport에 write.
  4. 리사이즈: 타일 크기 변경 → fit addon이 cols/rows 재계산 → session_resize(id, cols, rows) → SSH는 window-change, Telnet은 NAWS 전송 (시리얼은 no-op).
  5. 종료: 원격 종료 또는 사용자 종료 → 상태 이벤트로 프론트에 통지 → 타일에 "연결 종료" 표시.

5. IPC 설계

Tauri Commands

// 연결 프로파일 (serde tagged enum)
#[serde(tag = "type", rename_all = "snake_case")]
enum Profile {
  Serial { port: String, baud_rate: u32 },
  Ssh    { host: String, port: u16, username: String },
  Telnet { host: String, port: u16, username: String },
}

list_serial_ports() -> Vec<SerialPortInfo>          // 포트 드롭다운용
session_open(profile: Profile,
             cols: u16, rows: u16,
             on_output: Channel<OutputEvent>) -> SessionId
session_write(id: SessionId, data: Vec<u8>)
session_resize(id: SessionId, cols: u16, rows: u16)
session_close(id: SessionId)

// OutputEvent: Data(Vec<u8>) | Connected | Disconnected { reason } | Error { message }
// SSH 비밀번호는 프로파일에 저장하지 않고 연결 시점에 별도 인자로 전달

6. 타일 분할 설계

레이아웃을 이진 트리로 표현한다. 리프 노드는 하나의 pane(터미널 세션 또는 빈 타일), 내부 노드는 분할 방향과 비율을 가진다.

type LayoutNode =
  | { kind: "pane";  id: string; sessionId: string | null }
  | { kind: "split"; direction: "row" | "column";
      ratio: number;          // 0~1, 첫 자식 비율
      children: [LayoutNode, LayoutNode] }
  • 분할: 활성 pane을 split 노드로 치환하고 기존 pane + 새 pane을 자식으로 배치 (Ctrl+Shift+D 가로 / Ctrl+Shift+E 세로).
  • 닫기: pane 제거 시 형제 노드를 부모 위치로 승격.
  • 리사이즈: 분할선 드래그로 ratio 조정 → CSS flex-basis 반영 → 각 터미널 fit addon 재실행.
  • 포커스: 활성 pane 하나를 전역 상태로 관리, 키보드 입력·분할 명령의 대상.
  • 렌더링: 재귀 Svelte 컴포넌트 (TileNode.svelte가 자기 자신을 렌더) + flexbox. 트리 전체는 JSON 직렬화 가능하므로 마지막 레이아웃 복원도 store에 저장해 지원 가능.

7. 연결 이력 저장

tauri-plugin-store로 앱 데이터 디렉토리에 profiles.json을 저장한다.

{
  "profiles": [
    { "id": "uuid", "name": "장비 A 콘솔",
      "type": "serial", "port": "COM3", "baud_rate": 115200,
      "last_used": "2026-07-28T15:00:00Z" },
    { "id": "uuid", "name": "빌드 서버",
      "type": "ssh", "host": "192.168.0.10", "port": 22, "username": "admin",
      "last_used": "2026-07-27T09:30:00Z" }
  ]
}
  • 연결 성공 시 동일 설정 존재 여부를 확인해 last_used만 갱신, 없으면 새 항목 추가.
  • 목록은 last_used 내림차순으로 표시, 이름 변경/삭제/즐겨찾기 지원.
  • 비밀번호는 저장하지 않는다. 추후 저장이 필요해지면 OS 자격 증명 저장소(Windows Credential Manager)를 쓰는 keyring 크레이트로 확장.

9. 구현 로드맵

  1. M1 — 시리얼 단일 세션: xterm 단일 뷰 + serialport 연결, 포트 목록/baud 설정, 입출력 왕복 확인.
  2. M2 — 세션 추상화 + Telnet: Session trait / SessionManager 정리, Telnet(IAC 협상) 추가.
  3. M3 — SSH: russh 연결(비밀번호 인증), PTY + resize 처리.
  4. M4 — 타일 분할: 이진 트리 레이아웃, 분할/닫기/드래그 리사이즈, 세션-타일 연결.
  5. M5 — 연결 이력: plugin-store 프로파일 저장/목록/재연결 UI.
  6. M6 — 다듬기: 검색 애드온, 복사/붙여넣기, 폰트·테마 설정, 레이아웃 복원.
